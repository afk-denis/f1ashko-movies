# F1ashko — архив просмотров

Пассивный статический каталог на GitHub Pages. Поиск, сортировка, фильтры и пагинация работают в браузере по опубликованному JSON-снимку.

## Поток данных

Приватный Apps Script синхронизирует исходную Google-таблицу с копией и дополняет метаданные. Только этот приватный скрипт использует ключи Кинопоиска. Их нельзя добавлять в репозиторий или сайт.

GitHub Actions читает готовую копию таблицы без прав записи, создаёт `site/data/catalog.json`, проверяет результат и публикует `site`. Расписание: раз в 10 минут, на 3/13/23/33/43/53-й минутах; GitHub может задерживать запуски. Есть также запуск при push в main и ручной запуск владельцем через Actions. Посетители сайта не могут запускать workflow или импорт.

При открытии страницы выполняется одна попытка GET статического JSON с того же хоста. Нет кнопок обновления/повторной загрузки, периодического опроса, обновления при focus/visibility/online или случайных параметров URL для обхода кэша. Управление каталогом не отправляет запросов за данными. Новые снимки видны при следующем открытии или перезагрузке страницы с учётом обычного HTTP-кэша. Если начальная загрузка не удалась, доступен локально сохранённый снимок; повторных сетевых попыток не выполняется.

Постеры загружаются лениво как обычные изображения по сохранённым URL без API-ключа. Ссылки на запись, Кинопоиск и социальные страницы открываются только по действию посетителя. Фронтенд не обращается к Google Sheets, Apps Script или GitHub API.

## Границы безопасности

Удаление управляющих запросов из клиента изолирует импорт и квоты API от посещаемости. Это не абсолютная защита от DDoS: публичные статические файлы остаются доступны по HTTP, а доступность и ограничения хостинга определяет GitHub Pages. Сокрытие ссылки на исходную таблицу не является контролем доступа. Для текущего анонимного экспортёра таблице достаточно роли «читатель по ссылке» с разрешённым скачиванием; публичное редактирование не требуется.

При неудачном экспорте или тестах новый снимок не публикуется, последний успешный деплой остаётся доступен.

## Интерфейс

Поиск по названию; фильтры по жанру, году, стране, актёрам, режиссёрам и формату. Внутренний поиск вариантов, множественный выбор и синонимы action/экшн/боевик, horror/ужасы. Между фильтрами AND, внутри одного OR. Пагинация 12/24/48/96, сортировка, карточки/список и состояние в URL. В hero один счётчик всех записей, согласованный с общим количеством в списке; повторные просмотры не склеиваются. При фильтрации hero сохраняет общий итог, а список показывает число совпадений. Подпись «Обновлено» показывает время создания опубликованного снимка.

## Проверки

```sh
python3 scripts/export_catalog.py
python3 -m unittest discover -s tests -p 'test_*.py'
node --test tests/*.test.js
python3 -m http.server 8080 --directory site
```

`tests/ui_live.py` проверяет опубликованный интерфейс на компьютере и мобильных размерах. `tests/ui_refresh.py` теперь проверяет пассивный сетевой режим: одна загрузка JSON, отсутствие повторов после взаимодействий, событий вкладки и моделируемого часа, отсутствие записи/ключей/запросов к исходным API.

В Settings → Pages используется Source: GitHub Actions. Коммитить приватные Apps Script, ключи и XLSX нельзя. Генерируемый публичный JSON публикуется только в артефакте Pages.
