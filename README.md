# F1ashko — архив просмотров

Статический каталог записей стримов. Данные — из Google Sheets, только чтение. Отдельный приватный Apps Script синхронизирует оригинал и заполняет метаданные; секреты не входят в этот репозиторий.

## Публикация и актуальность данных

В Settings → Pages → Build and deployment выберите Source: **GitHub Actions**. Workflow `.github/workflows/pages.yml` читает актуальную таблицу, проверяет парсер и фильтры, публикует только каталог `site`. Запуск: push в main, вручную через Actions и каждые 10 минут по расписанию (3-я, 13-я, 23-я, 33-я, 43-я и 53-я минуты). GitHub может задерживать запуски: это не гарантированная синхронизация в реальном времени.

Изменения таблицы не требуют ручной пересборки. При публикации создаётся `data/catalog.json`; посетитель читает этот снимок, а не Google Sheets или API Кинопоиска напрямую. В футере показана дата снимка. Открытая видимая вкладка проверяет опубликованные данные каждые 5 минут и при возвращении на страницу, если предыдущая проверка была более 5 минут назад. Обновление не сбрасывает поиск, фильтры, сортировку, размер страницы и выбранный вид. Открытые диалоги и выпадающие фильтры не перерисовываются в ходе использования.

Кнопка «Проверить обновления» перечитывает последний опубликованный снимок, но не запускает API-импорт или workflow. Если публикация ещё не произошла, повторное нажатие не ускорит её. При недоступности данных показан последний сохранённый снимок с предупреждением; более старый ответ CDN не заменяет уже загруженные свежие данные.

Если чтение таблицы или тесты сборки не удались, новая версия не публикуется. Старый успешный деплой остаётся доступным. Посетитель не обращается к API Кинопоиска, API-ключи в браузер не передаются. Постеры загружаются по сохранённым URL изображений.

## Возможности

Поиск по названию; фильтры по жанру, году, стране, актёрам, режиссёрам и формату. Внутренний поиск вариантов, множественный выбор, синонимы action/экшн/боевик и horror/ужасы. Между фильтрами — AND, внутри одного — OR. Пагинация 12/24/48/96, сортировка, карточки/список, мобильный интерфейс и состояние в URL.

В hero один счётчик уникальных названий, без повторных просмотров. CTA, случайный просмотр и фильтр «только со ссылкой» удалены. Старый параметр `linked=1` игнорируется: записи без ссылки не скрываются неявно.

Повторные просмотры сохраняются. Объединённые ячейки ссылок распространяются только на собственный диапазон объединения. Числовые ID вида 484470.0 и 1.0355286E7 нормализуются без округления. Предварительные `legacy`-жанры не восстанавливаются в очищенные ячейки. Результаты с `Фильм API = ok` имеют отметку подтверждения; неподтверждённые данные не выдаются за результат API.

## Локально

Python 3.10+ и современный Node.js, npm-пакеты не нужны.

```sh
python3 scripts/export_catalog.py
python3 -m unittest discover -s tests -p 'test_*.py'
node --test tests/*.test.js
python3 -m http.server 8080 --directory site
```

Для браузерных проверок установите Playwright 1.57.0 и Chromium. `tests/ui_live.py` проверяет опубликованный сайт и реальные данные; тесты актёров/режиссёров отдельно используют синтетические записи. `tests/ui_refresh.py` проверяет последовательные тестовые снимки, автоматическое обновление, сохранение состояния, ошибки сети, защиту от старых данных и восстановление из кэша.

Для офлайн-проверки экспортируйте таблицу в XLSX и передайте `python3 scripts/export_catalog.py --input /path/to/export.xlsx`. Не коммитьте приватные скрипты, API-ключи и XLSX. Публичный сайт получает только публичный JSON.
